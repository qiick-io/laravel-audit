# Dependency register

Every runtime entry from the root `composer.json` `require` object is listed
below; `require-dev` is not. The register is reviewed at every release and in
every PR that changes `require`.

| Dependency                    | Version constraint | Why this minimum                                                                                                              | What we use                                                                                                                                                                                                                     | What we replace or extend and why                                                                                                                                                                          | Maintainer               | License | Known risk                                                                                                                                         | Exit plan within this package                                                                                          |
| ----------------------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `php`                         | `^8.4`             | `spatie/laravel-activitylog` v5, which the design and every product build on, requires PHP 8.4 (README), so the package cannot support 8.3.           | Language runtime: readonly classes and DTOs, enums, first-class callables across `src/`; CI runs 8.4/8.5.                                                                                                                          | Nothing to replace; platform requirement inherited from the audit-log dependency.                                                                                                                           | PHP Group                | PHP-3.01 | Products still on PHP 8.3 cannot adopt the package until activitylog v5 drops the floor or a v4-compatible line exists.                                                              | Not replaceable; revisit only if `spatie/laravel-activitylog` lowers its PHP floor.                                      |
| `illuminate/console`          | `^12.0 \|\| ^13.0` | Reserved for the `audit:purge` retention command the config documents (`audit.purge.schedule`); same major range as `illuminate/*`. | No `Illuminate\Console\*` class is imported yet — the purge command itself is pending (da verificare which PR lands it); `config/audit.php` already describes the daily schedule contract.                                                       | Will extend the console with a chunked two-pass purge command the product schedules, keeping retention explicit rather than a hidden scheduler.                                                              | Laravel (Taylor Otwell)  | MIT     | A required component with no current import is dead weight until the command lands; harmless because every Laravel app ships it.                                                                                     | If the purge moves to model pruning (`MassPrunable`) scheduled by the product, drop the component.                        |
